# ユーザーデータは meta.json に置き、SQLite は純粋なインデックスとする

「source のみで復元可能」というバックアップ要件と、タグ等のユーザー編集データを DB に持つ当初の DB 設計は矛盾していた(DB を消すとタグが全滅する)。タグ等のユーザー編集データはアセットディレクトリ内の `meta.json`(アセットメタ)に保存し、SQLite はソースからいつでも再構築できる検索用インデックスに徹することを決めた。これにより「cache と DB はいつ消してもよい」という基本設計方針が例外なく成立する。

## Considered Options

- **DB を「インデックス + ユーザーデータ」の二役にする** — 却下。基本設計方針を初日から破り、database.db のバックアップ義務が生まれる。
- **タグ・お気に入り等を MVP から落とす** — 却下。タグは MVP の検索要件に必要。

## Consequences

- source への書き込み経路は「新規アセット作成」と「meta.json(タグ)編集」の 2 つのみ。スキャンは読み取り専用。
- タイトル・カテゴリは meta.json にも DB にも持たない(ディレクトリ構造が正)。
- 将来のレーティング・コメント等のユーザーデータも meta.json に追加する(DB に置かない)。
