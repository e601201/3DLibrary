# ADR-0002: 生成ジョブの状態通知はポーリングで行う

## ステータス

採用(2026-07-25)

## コンテキスト

生成ジョブ(#6)・一括生成(#9)・キャッシュ管理(#11)は、直列キューの
進行状況(実行中のアセット・待機件数・エラー)を UI に表示する必要がある。
通知方式の候補はポーリング / SSE / WebSocket。

## 決定

**HTTP ポーリング**を採用する。

- `GET /api/jobs` がキューの現在状態を返す(実行中ジョブ・待機件数・
  バッチ進捗・直近のエラー)
- フロントエンドはキューが空でない間だけ 1 秒間隔でポーリングし、
  空になったら停止して一覧を再取得する

## 理由

- 127.0.0.1 専用・単一ユーザーのローカルアプリであり、ポーリングの
  ネットワークコストは無視できる(状態ペイロードは数百バイト)
- ジョブの粒度が粗い(Blender 起動 1 回 = 数秒〜数十秒)ため、
  1 秒の遅延は体感に影響しない
- SSE / WebSocket は接続の維持・再接続・プロキシ(Vite dev server)の
  考慮が増えるわりに、この規模では利点がない
- 状態の取得口が「現在状態を返す GET」1 つに揃うため、#9(一括生成)・
  #11(キャッシュ管理)も同じエンドポイントをそのまま使える

## 影響

- 進捗のリアルタイム性は最大 1 秒遅れる(許容)
- 将来、ログのストリーミング等で本当にプッシュが必要になった場合は
  SSE を追加で導入する(このときも `GET /api/jobs` は互換のまま残す)
