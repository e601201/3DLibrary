# ADR-0004: リモート閲覧の本人確認は Tailscale に委任する

## ステータス

採用(2026-08-07)

## コンテキスト

Windows 機で作ったアセットを Mac からも見たい。編集(Blender を開く)は
これまでどおり手元だけでよく、ネットワーク越しには本人だけが**見られれば**足りる。

3DLibrary は認証を持たず `127.0.0.1` のみで待ち受けるアプリとして作ってある
(requirements.md §3・§13)。これを保ったまま外から届かせる方法として、
次の 3 つが候補になった。

- **クラウドへデプロイする**: 第 2 の実行環境と、そこへ source を運ぶ仕組みが要る
- **source をファイル同期する**: 同上に加えて、.blend の容量をそのまま抱える
- **アプリにログインを実装する**: 認証・セッション・パスワード管理が増える

## 決定

1. 本人確認は **Tailscale のデバイス認証に全面委任**し、アプリは認証を持たない。
   tailnet に入れるのは自分のデバイスだけなので、アプリまで届いた時点で相手は本人である
2. 公開は **`tailscale serve`** が代理する。バイナリは今後も **loopback にのみ listen** する
3. リモート閲覧(CONTEXT.md)かどうかは、**どのポートに届いたか**で決める。
   `tailscale serve` の転送先を閲覧専用ポート(`127.0.0.1:8766`)に向け、
   そこへ届いた要求は **GET と HEAD 以外を一律 403** にする
4. クラウドへのデプロイ・source の同期・ログインの実装は**行わない**

## 理由

- **アプリのログインが守るものが残っていない**: ネットワーク層で「私である確認」が
  済んでおり、それでも残るのは「デバイスを物理的に触れる人」だが、
  そこはセッション残存のあるログインでは防げない
- **ポート分離は fail-closed**: 判定材料が「どのハンドラに届いたか」だけなので、
  要求の中身を信用せずに済む。ヘッダ判定(`Tailscale-User-Login` の有無)も可能だが、
  タグ付きデバイス発のトラフィックにはアイデンティティヘッダが付かず、
  「ヘッダが無い = ローカル」と読んでしまう fail-open になる(tailscale.com/kb/1312)
- **通す条件をメソッドだけで書ける**: 経路を列挙しないので、後から足した
  エンドポイントも(GET でない限り)最初から閉じている
- **保存要件がゼロ**: リモートで見せるものは GLB・サムネイル・スプライトとインデックスで、
  すべて既に配信済み。第 2 の実行環境も source の写しも要らない

## 影響

- **閲覧には Windows 機が起動している必要がある**。アセットを見せているのは
  クラウドではなく、いつもの 1 プロセスそのもの
- `.blend` の取得(`GET /api/assets/.../raw/...`)は**許す**。
  「リモートは GET/HEAD だけ」という 1 行の規則を保つため。
  リモートで「開けない」のは Blender を起動する操作の話であって、ファイルの話ではない
- **GET に副作用を持たせると、この防壁を素通りする**。副作用のある操作は
  必ず POST / PUT / DELETE で足すこと
- リモート閲覧を止めるのは `tailscale serve` を止めること。アプリ側に切り替えは無い
  (閲覧専用ポートは loopback にしか出ておらず、代理が無ければ誰にも届かない)
