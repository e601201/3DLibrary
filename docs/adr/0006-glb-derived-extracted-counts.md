# ADR-0006: 抽出メタデータの数は書き出した GLB を数える

## ステータス

採用(2026-08-16)

## コンテキスト

詳細画面のサイドバーが出す `OBJECTS` は `len(bpy.data.objects)`、つまり
**.blend の全オブジェクト数**だった。カメラ・ライト・アーマチュア・Empty・
エクスポート対象外のオブジェクトまで数に入る。一方 GLB に入るのはメッシュを
持つオブジェクトだけなので、両者は食い違う。手元の 59 件で測ると **41 件が
不一致**(クマリィ 14 対 11、SamekoSaba_島風コスプレ 67 対 65)。

CONTEXT.md は オブジェクト を「GLB の中で 1 つの Blender オブジェクトに
当たる単位」と定義している。つまり同じ「オブジェクト」という語が、同じ画面で
2 つの別のものを数えていた。GLB ビューワにオブジェクト一覧が入った
(#48)ことでこれが表面化する — `OBJECTS 82` の隣に 74 行の一覧が並ぶ。

数の出どころには 4 つの案があった:

1. **.blend のまま、ラベルを変える**: 生成の再実行が要らない。ただし GLB
   ビューワの隣で .blend の話をし続けることになり、用語の二重化は残る
2. **両方出す**: `.blend 82 / GLB 74` と並べる。情報量は最大だが、ユーザーに
   常に差分の意味を考えさせる
3. **Go がスキャン時に GLB を読んで数える**: 再生成なしで全件が即座に直る
   (実測で全 60 件のヘッダ読みは 124ms)。ただし数える規則が Python と Go の
   2 か所に増え、`polygonCount` とは出どころが分かれる
4. **生成時に書き出した GLB を数える**: `polygonCount` が既に通っている道

## 決定

案 4 を採る。generate.py は GLB を書き出したあとにその GLB を解析し、
**オブジェクト数・ポリゴン数・シェイプキー数**をそこから数える
(`glb_counts`)。オブジェクト 1 つ = **メッシュを持つ glTF ノード 1 つ**。
ボーンや Empty はノードであっても数に入らず、インスタンスは展開後の
ノードごとに 1 つと数える。

- `.blend` 側の `objectCount` / `shapeKeyCount` は書き出すのをやめる
- コレクション数・マテリアル数・テクスチャ数・アニメーション有無は
  引き続き .blend 側の統計(CONTEXT.md「抽出メタデータ」に明記)
- 抽出メタデータに世代印 `metadataVersion` を導入する。**印を持たない
  キャッシュの `objectCount` / `shapeKeyCount` は意味が違う**ので、UI は
  その 2 行を「—」にして「再生成すると表示されます」と添える
- GLB ビューワのオブジェクト一覧の見出しには総数を出す。読み込んだ GLB
  そのものの数なので、古いキャッシュでもここだけは必ず正しい

## 理由

- 用語集の オブジェクト は GLB 側の単位だと決まっている。数もそれに従うのが
  唯一の一貫した答えで、これで同じ画面の 2 つの数字が定義上ずれなくなる
- エクスポート結果を数えるので、エクスポータの除外規則・モディファイアーの
  適用・コレクションインスタンスの展開を自前で再現しなくて済む。案 3 と違い、
  この規則を保つ場所は 1 か所だけ
- 世代印を選んだのは、キーの意味の**差し替え**は「キーの有無」では見分けが
  つかないため。`glbObjectCount` のような別名を足す案は、同じファイルの中に
  意味の違う `objectCount` を残すことになり、今回のバグそのものを成果物に
  保存してしまう
- 既存キャッシュを一括で「要更新」にはしない。数字 1 つのために 60 件分の
  Blender 実行(スプライト 48 コマのレンダリング込み)を強制する価値はなく、
  一覧の見出しから真の数は読めるため

## 影響

- 既存の抽出メタデータは印を持たないので、再生成するまで `OBJECTS` と
  `SHAPE KEYS` が空欄になる。埋まるのは再生成した順
- 将来この数の意味をまた変える場合は `metadataVersion` を 2 に上げる。
  読む側の判定は `>= 1` で書いてあるので、しきい値を足す形で対応する
- `.blend` に何個オブジェクトがあるかは、どこにも出なくなる。エクスポート
  漏れの診断にその数が要ると分かったら、別の値として足すこと
  (`objectCount` を元の意味に戻してはいけない)
