# PRD: Hover Scrub Preview(スクラブプレビュー)

改訂: 2026-08-02(設計面談で確定。草稿からの主な変更は末尾)

## 概要

アセット一覧のグリッドカードにマウスを乗せると、カーソルの左右位置に連動して
モデルを様々な角度から見たレンダリング画像に切り替わる。YouTube のサムネイル
スクラブに相当する UX を、**スプライト**(CONTEXT.md 参照: 全周レンダリングを
1 枚に敷き詰めたキャッシュ画像)だけで実現する。GLB や Three.js は使わない。

## 背景・目的

静止サムネイル 1 枚では形状の奥行き・裏面・シルエットが把握できない。
一覧の高速性(GLB を読まない)を保ったまま、「クリックせずにモデル全体を
確認できる」体験を提供し、本当に開きたいアセットだけを選べるようにする。

## ユーザーストーリー

一覧画面で気になるアセットを、クリックせずに様々な角度から確認したい。
そうすることで、本当に開きたいモデルだけを選択できる。

## UX 仕様

### 操作モデル: ホバー位置スクラブ

- カード画像領域内のカーソル X 座標(領域幅に対する相対位置)を
  フレーム番号へ写像する: `frame = min(floor(x / width × 48), 47)`
- 左端 = フレーム 0(現行サムネイルと同じ角度)、右端 = 352.5°。
  右へ動かすほど一周する
- 押下は不要。カードのクリックは従来通り詳細画面への遷移として維持する
  (スクラブと干渉しない)
- ドラッグ回転は採用しない(詳細画面の GLB ビューワの役割)

### 状態遷移

- **通常時**: 静止サムネイル(現状のまま)
- **ホバー開始**: スプライトの取得・デコードを開始。完了までサムネイルを
  表示し続ける(スピナーは出さない。ローカル配信のため体感遅延はない)
- **スクラブ中**: カーソル位置のフレームを表示。カード下縁に細い
  ポジションバーを表示し、カーソル位置を追従させる。
  バーはスプライト表示が有効なときのみ出す
- **ホバー終了**: 静止サムネイルへ復帰し、スプライト要素を DOM から外す

### フォールバック

- スプライト未生成(`spritePath` が null)・不完全アセット:
  現状と同一挙動(静止表示・バーなし・追加の UI なし)
- 陳腐化したスプライト: そのまま表示する(既存の「要更新」バッジが知らせる)
- タッチ環境(`hover: none`): スクラブ無効。静止サムネイルのみ(v1 スコープ外)

## スプライト仕様

| 項目 | 値 |
|------|-----|
| フレーム数 | 48(7.5° 刻みで全周) |
| 1 フレーム | 512 × 512 px |
| 配置 | 8 列 × 6 行、行優先(左→右、上→下)、合計 4096 × 3072 px |
| 形式 | WebP(品質 80 目安)、背景透過 |

- カメラはサムネイルと同一の構図規則を使う: バウンディング中心を注視、
  現行の方向ベクトル `(1, -1, 0.7)` と同じ仰角、距離 = 半径 × 2.5、
  forest HDRI、AgX。これをワールド Z 軸周りに 7.5° 刻みで一周させる
- **フレーム 0 = 現行サムネイルと同一角度**(ホバー開始時に画像が飛ばない)
- フレームサイズは **512px 固定**。thumbnailSize 設定(256/512/1024)には
  連動させない(デコード後メモリの上限 ≈ 50MB を守るため)

## 保存・配信

- パス: `cache/sprites/{category}/{title}.webp`
  (`CachePaths` に追加、`cacheSubdirs` に `sprites` を追加)
- **source には一切書き込まない**(ADR-0003)
- API: `GET /api/sprites/{category}/{title}.webp` — 既存 `cacheFileHandler` を
  再利用し、`?v={asset.id}` のキャッシュバスターも他と同じ
- `Asset.spritePath: string | null` を追加(スキャンが stat で埋める)

## 生成

- 「生成」は **4 点**(GLB・サムネイル・抽出メタデータ・スプライト)を
  必ずまとめて作る(CONTEXT.md 改定済み)。全か無かを維持し、
  スプライトの失敗は生成の失敗。メタ JSON の書き出しを最後に行う
  成功マーカー方式も変えない
- generate.py: 既存フロー(メタ抽出 → テクスチャ解決 → GLB → サムネイル)の
  後に 48 フレームをレンダリングし、numpy(Blender 同梱)でシートに合成、
  Blender ネイティブの WebP 保存で書き出す。
  **外部依存を追加しない**(Pillow / cwebp / Go 側 WebP エンコーダ不要)
- キュー(直列・同時 1)・一括生成(不足分のみ)・ポーリング(ADR-0002)は
  変更なし。スプライト欠落は生成対象判定(needsGeneration)に含まれる
  ため、既存アセットは一括生成で自然に埋まる
- タイムアウトは 10 分のまま。超重量級アセットで超過が出た場合は、
  サンプル数(現 16)またはフレーム解像度を下げて対処する(ADR-0003 影響欄)

## スキャン・陳腐化

- スキャンはスプライトを stat し `SpritePath` を埋める(source は読み取り専用のまま)
- `isStale` にスプライトを追加: 欠落、または mtime < model.blend の mtime
- スプライトの寸法検査は v1 では行わない(512px 固定のため)

## フロントエンド実装指針

- スプライト表示は `background-image` + `background-size: 800% 600%` +
  `background-position` 切替を基本とする(`object-position` 方式でも可)
- `img.decode()` 等でデコード完了を検知してからサムネイルと切り替える
- 60fps: デコード済み単一テクスチャの `background-position` 変更のみで
  達成する(フレーム切替で再デコード・再レイアウトを発生させない)

## 非機能要件

- スクラブは 60fps で追従し、フレーム切替に体感遅延がないこと
- 一覧の初期表示で読み込むのはサムネイルのみ。GLB・Three.js 不使用を維持し、
  スプライトはホバー時にのみ取得する
- メモリ不変条件: スプライトはホバー中のカード 1 枚分だけ DOM に存在する
  (デコード済み最大 ≈ 50MB)。JS での明示的なキャッシュ管理・LRU は実装しない

## 対象外(v1)

- ドラッグ回転(詳細画面の GLB ビューワが担う)
- タッチ環境でのスクラブ
- リスト表示(行)でのスクラブ — グリッドのカードのみ
- スプライトの解像度・フレーム数の設定化
- 仰角のバリエーション(横一周のみ)

## 草稿からの主な変更

| 草稿 | 確定 | 理由 |
|------|------|------|
| `source/.../previews/sprite.webp` | `cache/sprites/{category}/{title}.webp` | スプライトは派生データ = キャッシュ(ADR-0003) |
| スプライト生成の位置づけ未定 | 生成の 4 点目(全か無か) | 状態モデルと UI を単純に保つ(ADR-0003) |
| スクラブと「ドラッグ回転」が併記 | ホバー位置スクラブに一本化 | クリック遷移と干渉せず、目的「クリックせずに確認」に合致 |
| 「スライダーを表示」 | 操作を持たない下縁ポジションバー | 位置写像方式ではスライダーは表示専用になる |
| スクロールアウトで解放・キャッシュ上限 | ホバー中のみマウントという不変条件 | ブラウザ管理と二重になる明示管理を排除 |
| フレーム数 24/36/48/72 から 48 を採用 | 48 × 512px・8×6・行優先で確定 | Retina 表示品質とデコード後メモリの均衡 |
